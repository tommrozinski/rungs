## Phase 2 — form and echo

Implemented the web layer per design.md §3 and the build-order step 3 (echo mode), copying
markup literally from prd/snapshot-form.html and prd/assessment-result.html with only the
allowed edits.

New main sources (package com.rungs.readiness.web):
- SnapshotForm: plain mutable JavaBean (not a record) with getters/setters, so Spring's
  classic WebDataBinder can auto-grow `List<SnapshotForm.DebtRow> debts` for indexed
  properties (debts[0].label, ...). All scalar fields are raw Strings, defaulted to "";
  booleans (rents, intendsToFundCollege, retired) default to false, matching "unchecked
  boxes -> false". DebtRow nested static class mirrors the six field names from the mock's
  JS (label, type, balance, annualInterestRate, minimumPayment), type defaulting to

- SnapshotController: GET / builds an empty SnapshotForm with one empty DebtRow and renders
  "form". POST /debts/add appends a DebtRow and re-renders "form". POST /debts/remove/{index}
  removes that row if 0 <= index < size (out-of-range index silently ignored) and re-renders
  "form". POST /assess builds the echo text and renders "result". @InitBinder sets
  binder.setAutoGrowCollectionLimit(100). An @ExceptionHandler(InvalidPropertyException.class)
  catches the case where the binder still can't reach an index (e.g. debts[99999] against an
  empty/short list or past the grow limit) and returns 400 instead of letting it surface as a
  500.
- SnapshotEcho: package-private helper that renders the submitted SnapshotForm as
  "name=value" lines (including every debt row), used only for the phase-2 echo panel at the

## Phase 3 — real result page

Implemented the real seven-stage assessment on the result page per design.md 038 section 4,
replacing the phase-2 echo. TDD throughout: one failing test at a time for the lenient
conversion and the copy rules, then the controller checkpoint tests.

New main sources (package com.rungs.readiness.web):
- SnapshotFormMapper: package-private final class, one static method
  `toSnapshot(SnapshotForm)` -> FinancialSnapshot. Lenient per design.md section 3 and the
  addendum: money fields parsed as BigDecimal (not Money.parse, so a value with more than two
  decimal places rounds half-up to the cent instead of being rejected); blank, unparseable,
  negative, or overflowing amounts become $0. Percent fields (retirement contribution, each
  debt's annual interest rate) parsed the same lenient way, then clamped to 0-100 and rounded
  half-up to the scale the domain requires (2 for retirement, 3 for interest rate), so an
  over-precise value never trips the domain's Invariants.percent rejection. A debt row whose
  parsed balance is exactly $0 is dropped before it reaches the domain. A blank label becomes
  "Debt N", where N is the row's 1-based position in the submitted list (before any rows are
  dropped). An unrecognized or blank debt type becomes DebtType.OTHER. Kept debts get
  positional ids ("debt-1", "debt-2", ...) counted among the kept rows only, matching the
  convention in FinancialSnapshotBuilder. emergencyFundMonths is fixed at 3, mortgage is
  always null, and monthlyCollegeContribution is fixed at $0 — the v0 form collects none of
  these. HouseholdFlags map directly from the three checkboxes.
- StageView (record): one ladder row's rendering data — stage number, title, chip
  label/class, disc class/content, whether this is the open/current stage, the line shown
  either as the small text or (when open) the blocker paragraph, and whether/how wide the
  progress bar is.
- ResultView (record): the whole result page's view model — eyebrow, verdict line/sub, the
  three formatted stats (with a surplusPositive flag for the green stat), and the seven
  StageViews in order.
- ResultViews: package-private final class, one static method
  `build(LadderResult, FinancialSnapshot)` -> ResultView. Builds every piece of copy in
  design.md section 4's table from the ladder's StageEvaluations (status, percentComplete,
  remainingAmount) plus a few raw snapshot figures the evaluators don't expose (the actual
  starter/full-emergency-fund balances, the 3-month expense target, the retirement percent,
  and the household flags for stage 5's two skip variants). None of the seven evaluators
  were changed; their own blocker/skip-reason strings are superseded by this class's copy
  (reused as-is only for stage 6's "You rent..." skip line, which already matched verbatim).
  Money is formatted with no cents when whole ("$12,480") and two decimals otherwise
  ("$500.50"). Counts and point gaps of one to ten are spelled out ("Three debts remain...",
  "Nine points to go."); above ten, or non-whole, they fall back to digits. Singular/plural
  agreement covers "debt"/"debts", "remains"/"remain", and "month"/"months". The disc/chip
  mapping is generic by StageStatus (SATISFIED -> done/Done, SKIPPED -> skipped/Skipped,
  IN_PROGRESS -> active/In progress, NOT_STARTED -> plain/Not started, except the current
  stage's disc is always "active" even when NOT_STARTED). The progress bar renders only for
  stages 1, 3, and 4 while IN_PROGRESS, at the evaluator's own percentComplete truncated to a
  whole percent.
- SnapshotController: constructs the real StageLadder (all seven evaluators) once, in the
  constructor. POST /assess now builds a FinancialSnapshot via SnapshotFormMapper, runs
  `ladder.assess(snapshot)`, builds the ResultView via ResultViews.build, and renders
  "result" with that as the "result" model attribute. The `echo` model attribute and
  SnapshotEcho.java are removed entirely.

Template (src/main/resources/templates/result.html): the static example ladder and the echo
section are both gone. Markup, classes, and inline `style="..."` attributes are otherwise
unchanged from the literal board copy — only `th:` attributes were added:
- `th:utext` (not `th:text`) for the eyebrow, verdict line/sub, stage titles, and chip
  labels, because Thymeleaf's `th:text` HTML-escapes apostrophes as `&#39;` in text nodes,
  which would have broken copy like "You're..."; none of this text is user-supplied, so
  rendering it unescaped is safe. Stage 2's line additionally needs `th:utext` because its
  bold amount is written as a literal `<b>...</b>` substring the view model produces, per
  the checkpoint's exact expected markup `totalling <b>$12,480</b>.`.
- The stat grid's "Monthly surplus" value keeps its base classes `class="v num"` and adds
  `th:classappend="${result.surplusPositive} ? 'pos' : null"`, rendering identically to the
  old hardcoded `class="v num pos"` when positive, and without the modifier otherwise.
- The ladder is one `th:each="s : ${result.stages}"` over the seven StageViews. Each stage's
  disc keeps `class="disc"` and adds `th:classappend="${s.discClass}"` (null for a plain
  disc, so no stray trailing space is added, matching the original mock's bare
  `class="disc"` for a not-started, not-current stage). `th:if="${s.open}"` /
  `th:unless="${s.open}"` pick between the plain `.stage-body` (small text, optional bar)
  and the `.stage-open` card (blocker paragraph), reproducing the two body shapes already in
  the literal markup. The bar's inline `style="width:NN%"` is rendered via
  `th:style="'width:' + ${s.barWidthPercent} + '%'"`, matching the mock's exact
  no-space-after-colon format.

Wording decisions beyond the design.md section 4 table (none of the checkpoint text
depends on these; they cover cases the table leaves implicit or that are unreachable in v0):
- Stage 6 (mortgage) IN_PROGRESS/NOT_STARTED has no table entry (the v0 form never collects

  So the stage-7 verdict line/sub ("Build wealth and give." / "Every earlier stage is done
  or skipped.") and the "all done" eyebrow always appear together in practice; there is no
  separate "stage 7 is current but unsatisfied" case to word.
- The small-text line's `style="margin-top:6px;"` (seen in the board mock only on stage 4,
  the one in-progress-with-bar example available) is applied generically whenever a stage's
  bar is shown, for stages 1 and 3 as well as 4, since no other convention is given.
