Review fixes
- HIGH: `projection/page.html`'s `#projection-controls` trigger was `input changed delay:250ms`.
  htmx's `changed` modifier caches the last dispatched value per element; a radio's `value` never
  changes, so re-clicking an already-checked strategy radio (Snowball -> Avalanche -> Snowball)
  was silently suppressed and the results went stale. Changed to `hx-trigger="input delay:250ms"`
  (no `changed`); `hx-sync="this:replace"` still discards any now-stale in-flight request.
  Deviation recorded in design.md Sec.2 under "030 projection screen". Updated the two markup
  tests that pinned the old attribute value (`ProjectionPageTemplateTests`,
  `ProjectionPageControllerTests`) and added
  `controlFormTriggerOmitsChangedSoReclickingTheSameStrategyRadioStillFiresARequest`, asserting
  the trigger does not contain "changed", with a comment explaining why.
- MEDIUM: added hostile-index and tampered-parameter tests to `ProjectionPageControllerTests`,
  mirroring `AssessmentPageControllerTests` / `SnapshotFormControllerTests`: out-of-range
  `debts[256]`/`debts[99999]` -> 400 on all three routes (`/projection`, `/projection/results`,
  `/projection/schedule`); a sparse `debts[200]` -> status < 500 on all three; tampered
  `strategy=X`/blank and `extraMonthlyPayment=-5`/`abc` -> never 5xx (form re-render on
  `/projection`, 400 on the two fragment routes). All passed against the existing
  `SnapshotBindingAdvice`/`SnapshotValidator` wiring with no production code changes needed.
