Implementation progress: 041 snowball and payoff dates

Phase 2 — domain
-----------------
Scope: design.md sections 1, 3, and 5 (snowball ordering, the two schedule payoff-date helpers, and maturity
removal), plus the minimal web changes needed to keep everything compiling and green.

What changed:

1. Snowball order (design.md 041 section 1). `PayoffScheduleCalculator.orderedLoans` now sorts debts by starting
   balance ascending (`Comparator.comparing(Debt::balance)`, a stable sort so ties keep the supplied order), then
   appends the mortgage last, unconditionally, exactly as before. The hand-verified cascade test was reworked with
   a debt that has a smaller balance but a lower rate than the other, so the new order provably differs from the
   old rate-descending order (see the corrected hand table in
   PayoffScheduleCalculatorTests.handVerifiedTwoDebtCaseMatchesTheFirstThreeMonthsExactly's comment). The ordering
   test and the "mortgage always last" test were reworked the same way (balance-based scenarios instead of
   rate-based ones).

2. Payoff-date helpers (design.md 041 section 3). `ScheduleLoan` gained a `boolean mortgage` component so
   `PayoffSchedule` can tell mortgage rows from debt rows without string-matching on the name "Mortgage".
   `PayoffSchedule` gained a `YearMonth asOf` component (so the payoff-date helpers have a month to report even
   with zero loans, when `months` is empty) and two instance methods:
     - `Optional<YearMonth> debtFreeMonth()`: the latest of every non-mortgage loan's closing month (the first
       month its `LoanMonth.end()` is zero), empty if any debt never closes within the schedule. With no debts at
       all (renter or mortgage-only), returns `Optional.of(asOf)` — documented on the method and the record's
       `asOf` component as the chosen representation of the "trivially already debt-free" case.
     - `Optional<YearMonth> mortgagePayoffMonth()`: the mortgage row's own closing month, empty if there is no
       mortgage row or it never closes within the schedule.
   Both are computed from the existing `loans`/`months` data (no additional per-month bookkeeping needed).

3. Maturity removal (design.md 041 section 1). `Mortgage` no longer has a `maturity` component (now a 3-arg
   record: balance, annualInterestRate, monthlyPayment). `MortgagePayoff` dropped `maturityComparison` and
   `monthsDifference`; `MortgagePayoff.MaturityComparison` is gone. `MortgagePayoffCalculator.payoff` no longer
   takes or compares against a maturity — it just returns `principalAndInterest`, `firstMonthInterest`, `covered`,
   `monthsToPayoff` (null if not covered or capped), and `payoffMonth`. `MortgageEvaluator`'s blocker is now only
   the current-payment sentence, per design.md 041 section 2:
     - covered and finishes: "At your current payment it's paid off in {Month YYYY}."
     - not covered: "Your $P payment doesn't cover the $I monthly interest." (unchanged wording)
     - capped: "At your current payment it won't be paid off within 50 years." (new wording, was "This payment
       won't pay the loan off within 50 years.")
   The duration/maturity-comparison helpers (word/duration/monthYear-follow-up) were deleted from
   MortgageEvaluator; only `monthYear` remains, for the payoff-line sentence.

Web stopgaps (minimal, compile-keeping only; full copy/ResultViews/templates work is phase 3):
  - `SnapshotFormMapper` no longer reads `maturityMonth`/`maturityYear` from the form at all (the mapper's
    `maturity(...)`/`parseInt(...)` helpers and the maturity range constants were deleted). `SnapshotForm`'s
    maturity fields and `form.html`'s maturity inputs are untouched — they still round-trip through
    `/edit`/`/debts/add` etc. as plain hidden-field echoes, just no longer consumed into the domain.
  - `SampleHouseholds.debtFree()`/`homestretch()` no longer compute or set a maturity (the `matchingMaturity`/
    `setMaturity`/`HOMESTRETCH_AHEAD_MONTHS` machinery was deleted); `byId(id, asOf)` keeps its `asOf` parameter
    for the caller's (SnapshotController's) sake, but no sample branch uses it anymore.
  - `ResultViews.stage6VerdictSub` was not touched — it already only used `covered`/`monthsToPayoff`/
    `payoffMonth`, none of which moved.
  - `ScheduleViews` was not touched — it doesn't read `ScheduleLoan.mortgage()` or the new schedule helpers.

Test changes beyond straightforward constructor-arg fixups:
  - `MortgagePayoffCalculatorTests`: removed the maturity-comparison test group and the two zero-balance/maturity
    tests that relied on it (11 tests remain, all payoff-shape tests, unchanged behavior).
  - `MortgageEvaluatorTests`: replaced the maturity-follow-up tests (matches/ahead/behind/singular-duration) with
    one test per current-payment branch (not covered, payoff line, capped); 6 tests, matching the new blocker
    contract exactly.
  - Deleted `SampleHouseholdsTests` and `SampleHouseholdMaturityAcrossClocksTests` outright: both tested the
    debt-free/homestretch maturity computation, which design.md 041 section 1 removes entirely.
  - `SnapshotFormMapperTests`: removed the four maturity-parsing tests (`maturityMonthOutsideOneToTwelve...`,
    `maturityYearOutsideTheAllowedRange...`, `blankMaturityFieldsBecomeUnknown`,
    `unparseableMaturityFieldsBecomeUnknown` — `Mortgage.maturity()` no longer exists to assert against); added
    `mortgageModeIgnoresTheMaturityFields` in their place, asserting the posted maturity fields have no effect on
    the mapped `Mortgage`.
  - `SnapshotControllerTests`: the two sample-maturity assertions ("value=\"2044\"...", "value=\"2038\"...") on
    `loadSampleFillsTheFormWithThe{DebtFree,Homestretch}Household` were dropped (the samples no longer compute
    those values). `assessAssignsTheDebtFreeSampleHouseholdToStageThreeMatchingItsMaturity` and
    `...HomestretchSampleHouseholdToStageSixAheadOfItsMaturity` were renamed to
    `...AndIgnoresThePostedMaturityFields` and stripped of their maturity-comparison-text assertions ("That
    matches your loan's", "ahead of your"); stage-assignment assertions (unaffected, since stage assignment never
    depended on maturity) were kept, and the homestretch one gained an assertion on the new current-payment
    sentence instead.
  - `PayoffScheduleControllerTests.breakdownRendersTheFirstMonthFiguresAndLoanNamesInPayoffOrder`: the board
    household's three debts (Store card $840/26.99%, Car loan $9,140/6.40%, Student loan $2,500/4.50%) render in
    balance order under the snowball (Store card, Student loan, Car loan, Mortgage) rather than the old rate order
    (Store card, Car loan, Student loan, Mortgage); updated the ordering assertions accordingly. The first-month
    dollar-figure assertions were untouched since Store card is first under both orderings.

Phase 3 — web
-------------
Scope: design.md 041 sections 1, 2, and 4 (carry the mocks forward, the result-page copy driven by the payoff
schedule, and the schedule page's title/subtitle), plus the web-side maturity removal deferred from phase 2.

What changed:

1. Maturity removal (design.md 041 section 1). Deleted `maturityMonth`/`maturityYear` from `SnapshotForm` (fields
   and getters/setters), the maturity `<select>`/`<input>` block from `templates/form.html` (the mock's mortgage
   card has no maturity fields at all — carried forward verbatim, paragraph moved up to sit directly under the
   payment field), the two maturity hidden fields from `templates/result.html`'s "Change my numbers" round-trip
   form, and the now-dead `.housing-mortgage .field-row.maturity-row` rule from `rungs.css`. `SampleHouseholds
   .byId` dropped its unused `asOf` parameter (`SnapshotController.loadSample` updated to match); no sample ever
   read it once phase 2 removed the maturity computation.

2. Schedule computed once per `/assess` (design.md 041 build order, item 3). `SnapshotController.assess` now calls
   `PayoffScheduleCalculator.schedule(snapshot)` unconditionally (not only when `breakdown=true`) and passes the
   same `PayoffSchedule` to both `ResultViews.build` (for stage 2/6 copy) and, when `breakdown=true`, to
   `renderPayoffSchedule` for the inline iframe — replacing its former re-computation from the snapshot. `/breakdown`
   (the standalone page) still computes its own schedule from its own posted form, independently, as before.

3. Result-page copy (design.md 041 section 2). `ResultViews.build` takes a third `PayoffSchedule` parameter,
   threaded into `stageView`/`stageLine`/`verdictSub`:
   - **Stage 2 verdict sub** (`stage2VerdictSub`, new): from `schedule.debtFreeMonth()` — "With the debt snowball
     you're free of everything but the house by {date}, about {N} months from now" (singular "1 month"), where N
     counts the schedule's own `asOf` month as month one (`ChronoUnit.MONTHS.between(schedule.asOf(), date) + 1`);
     or the fixed "At these payments your debts won't be paid off within 50 years." when the schedule's debts never
     all close.
   - **Stage 6 line** (`stage6Line`, reworked): unchanged for Done/Skipped; for the open case, still starts from
     `evaluation.blocker()` (the current-payment sentence, unchanged in the domain) and appends a snowball
     sentence via `snowballComparison`/`snowballSuffix` when the schedule's `mortgagePayoffMonth()` beats the
     current-payment payoff (or the current payment has no payoff date to compare against) — with the "{duration}
     sooner" clause only when there is a current-payment date to measure against.
   - **Stage 6 verdict sub** (`stage6VerdictSub`, reworked): the same comparison, phrased as "...sooner than your
     payment alone." (or just the date with no comparison); falls back to calling `stage6Line` itself when the
     snowball doesn't finish sooner than the current payment (covers both "never closes" and "closes but not
     sooner").
   - **All-done eyebrow**: "Every stage that applies to you is done" (was "All seven stages are done or skipped").
   - Added a private `SnowballComparison(YearMonth date, String duration)` record and a `snowballComparison(...)`
     helper shared by both stage-6 call sites, so the "does the snowball help, and by how much" logic lives in
     exactly one place. Added a `duration(YearMonth, YearMonth)` helper ("Y years M months", singular forms and
     zero parts omitted) — phase 2 had already deleted `MortgageEvaluator`'s old duration/maturity-comparison
     helpers entirely (design.md 041 section 1), so there was nothing left to reuse; this is a fresh, single-
     location implementation rather than a duplicate. `monthYear` is unchanged and still the one date formatter.

4. Schedule page (design.md 041 build order, item 1 carried into templates). `templates/payoff-schedule.html`'s
   title and subtitle now read "🏦 Payoff schedule — debt snowball (smallest balance first)" and "Your surplus goes
   to the smallest debt; each paid-off debt's payment rolls into the next. The mortgage comes last." — copied
   verbatim from `prd/payoff-schedule.html`. `ScheduleViews` itself was untouched, as expected (loan order already
   came from the snowball-ordered `PayoffSchedule` since phase 2).
